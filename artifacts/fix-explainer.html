Querier OOMKills — one allocation per returned log line

pkg/querier/queryrange · the merge that assembles the final page of a split log query

The defect

  • When a log query's splits return more entries than the requested limit, the final page is assembled by draining a priority queue of per-label streams.
  • Popping the head re-pushed a copy of it so the remaining entries stayed on the heap, costing one throwaway logproto.Stream for every entry emitted.
  • The queue is drained exactly limit times, so a query returning 5,000 lines churned 5,000 short-lived objects — into the same heap the read path is already straining.
  • Crossing the limit threshold flipped the same query from 811 to 101,128 allocations.

The change — pkg/querier/queryrange/ordering.go

before — copies the head 
func (pq *priorityqueue) Pop() interface{} {
    n := pq.Len()
    stream := pq.streams[n-1]
    pq.streams[n-1] = nil
    pq.streams = pq.streams[:n-1]

    // put the rest of the stream back
    if len(stream.Entries) > 1 {
        remaining := *stream   // allocates
        remaining.Entries = remaining.Entries[1:]
        heap.Push(pq, &remaining)
    }
    stream.Entries = stream.Entries[:1]
    return stream
}
after — advances in place 
// popEntry returns the next entry in direction
// order. Draining the queue does not allocate.
func (pq *priorityqueue) popEntry() (string, logproto.Entry) {
    head := pq.streams[0]
    labels, entry := head.Labels, head.Entries[0]

    if len(head.Entries) > 1 {
        head.Entries = head.Entries[1:]
        heap.Fix(pq, 0)
    } else {
        heap.Pop(pq)
    }

    return labels, entry
}
